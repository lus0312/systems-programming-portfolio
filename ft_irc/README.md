# ft_irc — Linux 논블로킹 TCP 기반 IRC 서버

## 어떤 과제인가요?

ft_irc는 여러 사용자가 채널에 참여하고 메시지를 주고받을 수 있는 IRC 서버를 C++98로 구현하는 42의 네트워크 프로그래밍 과제입니다. IRC는 서버에 연결한 사용자들이 채널이나 개인 메시지로 대화하는 텍스트 기반 통신 방식입니다.

핵심은 채팅 명령을 처리하는 데서 나아가, TCP로 들어오는 데이터를 메시지로 해석하고 여러 연결의 상태를 관리하는 것입니다. 이 프로젝트에서는 Linux의 논블로킹 소켓과 `poll()`을 사용해 하나의 이벤트 루프에서 클라이언트의 접속·수신·송신·종료를 처리했습니다.

## 구성과 담당 내용

3인 팀으로 과제의 필수 기능을 구현했으며, 2026년 6월 평가를 완료했습니다. 메시지·명령어 파싱은 팀원이 담당했고, 저는 소켓과 연결 관리, 인증·등록, 명령 실행, 채널 관리, 메시지 전달과 연결 종료를 구현했습니다.

| 구성 요소 | 역할 | 연결 |
| --- | --- | --- |
| `Server` | 소켓과 poll 이벤트 관리, 데이터 수신·송신 | 클라이언트 소켓 ↔ Controller |
| `Message` | 수신한 명령행을 명령과 인자로 분리 | 명령행 → Controller |
| `Controller` | 인증·명령 실행, 응답 생성, 사용자·채널 관리 | Message, Client, Channel |
| `Client` | 사용자 정보와 등록 상태, 수신·송신 버퍼 보관 | 연결별 데이터 관리 |
| `Channel` | 참여자·운영자·초대 목록과 채널 모드 관리 | 여러 Client의 채널 참여 상태 |

```text
IRC 클라이언트 → TCP 소켓 → Server / poll
                              │
                         수신 버퍼 누적
                              │
                     명령행 분리 → Message
                                      │
                                  Controller
                                  /        \
                              Client     Channel
                                  │
                              송신 버퍼
                                  │
IRC 클라이언트 ← TCP 소켓 ← Server / POLLOUT
```

## 주요 구현

- Linux 소켓에 `O_NONBLOCK`을 적용하고 `poll()`로 여러 연결의 읽기·쓰기 준비 상태 감시
- `PASS`, `NICK`, `USER`를 통한 인증·등록과 닉네임 중복 확인
- `JOIN`, `PART`, `QUIT` 및 사용자·채널 대상 `PRIVMSG` 처리
- `TOPIC`, `KICK`, `INVITE`와 채널 모드 `i`, `t`, `k`, `o`, `l` 구현
- 클라이언트별 수신 데이터를 누적하고 CRLF를 기준으로 명령행 분리
- 부분 송신 후 미전송 데이터를 송신 버퍼에 유지하고, `EAGAIN`·`EWOULDBLOCK` 발생 시 다음 `POLLOUT` 이벤트에서 재시도
- 채널 이름의 대소문자 비교 통일, 연결 종료 시 공통 채널 사용자에게 알림
- 송신 메시지 길이 제한과 긴 NAMES 목록의 응답 분리

닉네임은 최대 30자로 제한합니다. 송신 메시지는 CRLF 포함 512바이트에 맞추며, 긴 텍스트 본문은 길이를 제한합니다. 클라이언트별 송신 버퍼가 32 MiB를 초과하려는 경우 해당 연결을 종료 대상으로 표시합니다.

## 문제 해결: 수신이 지연되는 클라이언트와 동작 검증

클라이언트가 연결되어 있어도 항상 데이터를 읽고 있는 것은 아닙니다. 이를 확인하기 위해 같은 채널의 클라이언트 하나를 일시 정지하고, 다른 클라이언트에서 대량의 메시지를 보내는 테스트를 진행했습니다.

테스트에서는 실행 중인 클라이언트가 메시지를 계속 수신하고, 정지했던 클라이언트도 재개 후 메시지를 수신하는 것을 확인했습니다. 구현에서는 연결별 송신 버퍼에 미전송 데이터를 남기고, 소켓이 쓰기 가능한 상태가 되었을 때 다시 전송하도록 구성했습니다. 이 과정에서 메시지를 만드는 일과 실제 소켓으로 전달하는 일을 분리해 생각하게 됐습니다.

또한 자체 서버에서 예상한 응답이 나온다는 것만으로 구현을 판단하기 어려웠습니다. Libera.Chat에 접속해 실제 서버의 응답과 상태 변화를 관찰하고, 이를 비교 자료로 활용했습니다. `irssi`, `nc`와 테스트 스크립트로 정상적인 채팅뿐 아니라 메시지 분할 전송, 다중 접속과 비정상 종료도 확인했습니다.

## 배운 점

### TCP 데이터와 메시지 경계

한 번의 수신이 IRC 명령 하나와 일치한다고 가정할 수 없습니다. 데이터가 나뉘어 들어오거나 여러 명령이 함께 들어오는 경우를 다루면서, 수신 버퍼에 데이터를 모으는 단계와 완성된 명령을 처리하는 단계를 구분했습니다.

### 연결별 상태와 공유 상태

인증 정보와 수신·송신 버퍼는 사용자별로 관리하고, 채널의 참여자·운영자·모드는 여러 사용자가 공유하는 상태로 관리했습니다. 명령 처리 결과가 메시지 출력뿐 아니라 이후 접근 권한과 연결 정리에도 영향을 준다는 점을 다뤘습니다.

### 정상 동작 밖의 상황을 검증하는 방법

클라이언트의 수신을 멈추거나 명령을 나눠 보내는 방식으로, 정상적인 대화만으로는 확인하기 어려운 상황을 만들었습니다. 외부 서버 관찰과 통신 기록을 함께 보면서 기능의 성공 여부뿐 아니라 상태 변화와 오류 응답도 확인하는 방향으로 테스트를 넓혔습니다.

### 학습 방법

실제 IRC 클라이언트와 외부 서버를 사용해 동작을 관찰하고 코드와 비교했습니다. AI의 도움으로 마련한 테스터를 활용해 테스트 시나리오와 통신 trace를 확인했습니다.

## 실행 준비

Linux 환경과 C++ 컴파일러, GNU Make가 필요합니다. 아래 명령은 `ft_irc` 폴더 안에서 실행합니다.

```bash
make
./ircserv 6667 local-test-password
```

다른 터미널에서 `irssi`로 접속합니다.

```bash
irssi -c 127.0.0.1 -p 6667 -w local-test-password -n alice
```

접속 후 `/join #portfolio`로 채널에 입장합니다. 두 번째 클라이언트는 다른 닉네임을 사용하면 됩니다.

Python 3가 설치되어 있으면 테스터로 서버를 실행하고 결과를 확인할 수 있습니다.

```bash
python3 ft_irc_tester_trace.py --spawn ./ircserv --port 6667 --password local-test-password --trace
```

`test_partial.sh`는 포트 `6667`, 비밀번호 `secret`을 사용하도록 작성되어 있으므로 실행할 서버의 설정과 맞춰야 합니다.

빌드 결과물은 `objs/`에 저장됩니다. `make clean`은 빌드 결과물을, `make fclean`은 실행 파일까지 제거합니다. 실행 중인 서버는 `Ctrl+C`로 종료할 수 있습니다.
