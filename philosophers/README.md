# Philosophers — pthread 기반 스레드와 동기화

## 어떤 과제인가요?

Philosophers는 식사하는 철학자 문제를 C로 구현하는 42의 동시성 프로그래밍 과제입니다. 철학자들은 원형 테이블에 앉아 식사·수면·사고를 반복하며, 식사하려면 양옆의 포크 두 개가 필요합니다. 마지막 식사를 시작한 뒤 제한 시간이 지나면 철학자가 사망하고 시뮬레이션이 종료됩니다.

핵심은 여러 스레드가 동시에 움직이는 상황에서 공유 자원과 상태를 안전하게 관리하는 것입니다. 이 프로젝트에서는 POSIX 스레드 라이브러리인 `pthread`로 철학자별 스레드를 생성하고, 포크별 mutex를 사용하며, 메인 스레드에서 식사 시각과 종료 조건을 확인하는 구조로 구성했습니다.

## 구성과 담당 내용

철학자의 행동 루틴, 공유 상태에 대한 동기화, 종료 조건 감시와 자원 정리를 구현했습니다. 프로그램은 철학자 수와 행동 시간을 입력받아 실행합니다.

| 구성 요소 | 역할 | 연결 |
| --- | --- | --- |
| 철학자 스레드 | 포크 획득, 식사·수면·사고 반복 | 양옆 포크와 공통 실행 상태 |
| 포크 mutex | 포크 하나에 대한 동시 접근 제한 | 인접한 철학자들이 공유 |
| 식사 상태 mutex | 마지막 식사 시각과 횟수 보호 | 철학자 스레드 ↔ 감시 루프 |
| 감시 루프 | 사망 또는 전체 최소 식사 횟수 달성 확인 | 메인 스레드에서 각 철학자 확인 |
| 종료·출력 mutex | 종료 상태 접근과 로그 출력 보호 | 전체 스레드가 공유 |

```text
메인 스레드 → 상태·mutex 초기화 → 철학자 스레드 생성
    │                                  │
    │                            포크 두 개 획득
    │                                  │
식사 상태 감시 ← 식사 시각·횟수 갱신 ← 식사
    │                                  │
    │                             포크 반환
    │                                  │
    │                             수면 → 사고 → 반복
    │
종료 조건 확인 → 종료 상태 설정 → 스레드 join → 자원 해제
```

## 주요 구현

- `pthread_create`로 철학자별 스레드를 생성하고, 종료 후 `pthread_join`으로 회수
- 포크별 mutex로 공유 자원 접근을 제어하고, 복수 포크의 획득 순서를 관리
- 철학자에 따라 포크 획득 순서를 다르게 구성
- 마지막 식사 시각·식사 횟수·종료 상태에 대한 mutex 보호
- 스레드 생성 완료 후 공통 시작 시각 설정
- 사망 또는 전체 최소 식사 횟수 달성 시 종료
- 포크가 하나뿐인 단일 철학자 처리
- 잘못된 숫자 입력과 정수 범위 초과 검사
- 일부 자원만 생성된 오류 상황에서 생성된 범위만 정리

소스는 초기화(`init.c`), 실행 관리(`main.c`), 행동 루틴(`routine.c`), 감시(`monitoring.c`), 보조 함수(`utils.c`), 자원 해제(`free.c`)로 나누었습니다.

## 문제 해결: 종료 시점과 자원 해제 순서

스레드는 생성 순서대로 실행을 마치는 것이 아니므로, 프로그램이 종료를 결정한 시점에도 다른 스레드가 공유 자원을 사용하고 있을 수 있습니다.

기존 구현을 다시 검토하는 과정에서 스레드 생성이 중간에 실패하면, 이미 실행 중인 스레드가 사용하는 mutex와 메모리를 먼저 해제할 수 있는 경로를 발견했습니다. 종료 상태를 알린 뒤 생성된 스레드를 `join`하고, 이후 자원을 해제하는 순서로 보완했습니다. mutex 초기화가 일부만 성공한 경우에도 초기화한 개수만큼만 정리하도록 수정했습니다.

이 문제는 정상 실행의 종료뿐 아니라 초기화 실패도 별도의 흐름으로 다뤄야 한다는 점을 보여줍니다. 자원을 생성하는 코드와 함께, 어느 시점에 누가 그 자원을 사용하는지와 언제 해제할 수 있는지를 확인하는 것이 중요했습니다.

## 배운 점

### 공유 상태의 읽기와 쓰기

마지막 식사 시각은 철학자 스레드가 갱신하고 감시 루프가 읽습니다. 공유 데이터를 변경하는 곳뿐 아니라 읽는 곳에서도 같은 동기화 규칙이 필요하다는 점을 다뤘습니다. 포크와 상태 변수의 mutex는 각각 보호하는 대상이 다릅니다.

### 자원 획득 순서와 대기

모든 철학자가 포크 하나씩을 잡고 다른 포크를 기다리면 순환 대기가 생길 수 있습니다. 포크 획득 순서를 다르게 구성하면서, mutex를 사용하는 것과 여러 자원을 어떤 순서로 획득하는 것은 별개의 설계 문제임을 다뤘습니다.

### 시간과 종료 조건

식사·수면·사망 시간을 밀리초로 관리하고, 대기 중에도 종료 상태를 확인하도록 구성했습니다. 최소 식사 횟수는 정확히 같은 순간만 찾는 대신 기준 이상인지 판단합니다. 시간 단위와 상태를 확인하는 시점이 실행 결과에 영향을 준다는 점을 다뤘습니다.

### 학습과 확인 방법

철학자가 한 명인 경우, 여러 명이 식사 횟수를 채우는 경우, 사망이 발생하는 경우와 잘못된 입력을 나누어 확인했습니다. WSL에서 수정된 프로그램을 실행하고 Valgrind로도 점검했습니다.

## 실행 준비

Linux 환경과 C 컴파일러, GNU Make, pthread가 필요합니다. 아래 명령은 `philosophers` 폴더 안에서 실행합니다.

```bash
make re
./philo 5 800 200 200 5
```

인자는 다음 순서입니다. 시간 단위는 밀리초입니다.

```text
./philo 철학자수 사망제한시간 식사시간 수면시간 [최소식사횟수]
```

최소 식사 횟수를 지정하면 모든 철학자가 해당 횟수를 충족할 때 종료합니다. 지정하지 않으면 사망이 발생하거나 사용자가 중단할 때까지 실행합니다.

```bash
# 철학자가 한 명이면 두 번째 포크를 얻을 수 없음
./philo 1 800 200 200

# 식사 시간보다 사망 제한 시간이 짧은 경우
./philo 2 60 150 30

# 잘못된 숫자 입력 거부
./philo 2abc 800 200 200
```

Valgrind가 설치되어 있으면 다음과 같이 메모리 사용을 확인할 수 있습니다.

```bash
valgrind --leak-check=full --show-leak-kinds=all ./philo 5 800 200 200 5
```

빌드 중 생성되는 `.o`와 헤더 의존성 `.d` 파일은 `objs/`에 저장됩니다. `make clean`은 빌드 결과물을, `make fclean`은 실행 파일까지 제거합니다.
